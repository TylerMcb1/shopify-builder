Shopify Builder — Implementation Plan

1. Product Summary

Shopify Builder is a local desktop application that lets a non-technical user modify Shopify themes using natural-language instructions.

The application wraps Claude Code behind a controlled GUI. Claude Code edits a local copy of a Shopify theme, while trusted application code handles Shopify authentication, theme retrieval, validation, Git history, and deployment.

The application may:

• Create a new unpublished theme for a change.
• Update an existing unpublished theme.
• Use the live theme as a read-only starting point.
• Preview unpublished themes.
• Maintain local Git-backed change history.
• Undo changes made to unpublished themes.

The application must never:

• Modify the live theme.
• Push files to the live theme.
• Publish an unpublished theme.
• Change which theme is currently live.
• Give Claude Code access to Shopify credentials.
• Give the renderer unrestricted shell access.

2. MVP Goals

The MVP must allow the user to:

1. Connect one Shopify store.

2. Enter a natural-language change request.

3. Select one of two target workflows:

  • Create a new unpublished theme.
  • Update an existing unpublished theme.
4. Select the base theme when creating a new theme.

5. View unpublished themes in a clear theme picker.

6. Generate changes locally with Claude Code.

7. Review a summary and changed files.

8. Run Shopify Theme Check.

9. Push validated changes to the selected unpublished theme.

10. Open the resulting Shopify preview.

11. Review local change history.

12. Undo the last application-generated change.

3. Non-Goals

The MVP will not support:

• Publishing themes.
• Changing the live theme.
• Editing checkout.
• Managing products, collections, orders, customers, or payments.
• Installing or removing Shopify apps.
• Editing third-party credentials or integrations.
• Multi-store management.
• Cloud synchronization.
• Team collaboration.
• Mobile support.
• Fully autonomous deployment.
• Arbitrary terminal access.

  +--> Git

The application has three security zones:

1. Renderer

  • Displays data and collects user actions.
  • Cannot run arbitrary commands.
  • Cannot access credentials directly.
2. Trusted main process

  • Owns credentials and deployment policy.
  • Validates every IPC request.
  • Executes allowlisted commands.
  • Rechecks theme safety before every push.
3. Claude Code workspace
  • Receives only the local theme and editing instructions.
  • Cannot receive Shopify credentials.
  • Cannot choose deployment targets.
  • Cannot publish or push themes.
  • Returns file changes and a summary to the trusted process.

6. Core Workflow

6.1 Application startup

1. Load local settings.
2. Verify required tools.
3. Verify Shopify connection.
4. Fetch the current theme list.
5. classify themes as live or unpublished.
6. Display the workspace screen.

The application should show actionable setup instructions if Claude Code, Shopify CLI, or Git is unavailable.

6.2 Create a new unpublished theme

1. User enters a change request.

2. User selects Create new unpublished theme.

3. User selects a base theme:

  • Current live theme, read-only.
  • Existing unpublished theme.
4. User supplies or accepts a generated theme name.

5. Main process refreshes the theme list.

6. Main process verifies the base theme still exists.

7. Application creates an isolated local workspace.

8. Shopify CLI pulls the base theme.

9. Git records the original snapshot.

10. Claude Code edits the local files.

11. Application inspects the changed files.

12. Shopify Theme Check runs.

13. User reviews the summary and diff.

14. Main process refreshes theme state again.

15. Shopify CLI creates a new unpublished theme.

16. Git records the deployed revision.

17. Application opens the preview URL.

7. Live-Theme Safety Policy

Live-theme protection is an application invariant, not merely a UI feature.

Mandatory safeguards

• Filter the live theme out of deployment-target selectors.
• Permit the live theme only as a read-only base theme.
• Resolve targets by immutable Shopify theme ID.
• Fetch fresh theme data immediately before every push.
• Reject targets whose role is main or equivalent.
• Reject missing or ambiguous targets.
• Never invoke a theme-publishing command.
• Never use Shopify CLI flags that permit live-theme modification.
• Do not expose a generic command-execution IPC endpoint.
• Keep Shopify credentials inaccessible to Claude Code.
• Maintain a strict command and argument allowlist.

Example safety check:

function assertSafeTarget(theme: ShopifyTheme): void {
  if (theme.role === "main" || theme.isLive) {
    throw new Error(
      "Shopify Builder cannot modify the live theme."
    );
  }
}The same check must run:

• When a target is selected.
• Before generation starts.
• Before a preview push.
• Immediately before an existing theme is updated.
• Before an undo operation.

8. Claude Code Integration

Claude Code acts only as a local theme-editing engine.

Inputs

Claude Code receives:

• The user’s request.
• The isolated theme workspace path.
• Shopify theme editing guidelines.
• Allowed file patterns.
• Prohibited actions.
• Relevant validation feedback during an approved repair cycle.

Allowed theme paths

assets/**
blocks/**
config/**
layout/**
locales/**
sections/**
snippets/**
templates/**Files outside these paths must be rejected unless explicitly added to the application policy.

Claude Code must not receive

• Shopify tokens.
• Store passwords.
• Credential-store values.
• Deployment commands.
• Permission to publish themes.
• Access to unrelated user directories.
• A generic instruction to operate the computer.

System instructions

Claude Code should be instructed to:
• Make only the requested storefront change.
• Preserve existing behavior unless necessary.
• Keep Shopify Liquid and schema JSON valid.
• Avoid destructive file deletion.
• Avoid checkout, analytics, tracking, app embeds, and credentials.
• Reuse existing theme patterns.
• Keep changes minimal and reversible.
• Return a concise summary and warnings.

Execution strategy

The preferred integration is a structured Claude Code invocation from the main process. The adapter should capture:

• Execution status.
• Structured events.
• Changed files.
• Completion summary.
• Warnings.
• Errors.
• Duration.

Claude Code never performs the Shopify push.

9. Shopify CLI Integration

Only the trusted main process may invoke Shopify CLI.

Allowed operation categories

• Authenticate or verify an existing session.
• List themes.
• Pull a specific theme.
• Run Theme Check.
• Create an unpublished theme.
• Push to a verified unpublished theme.
• Retrieve or construct preview URLs.

Forbidden operation categories

• Publish a theme.
• Push to the live theme.
• Use live-theme override flags.
• Delete themes in the MVP.
• Run arbitrary Shopify CLI commands supplied by the user or model.

Every process invocation must use an argument array instead of a shell-interpolated command string.

10. Git and Local History

Each theme operation uses an isolated Git repository or worktree.

Suggested commit sequence:

• Change ID.
• Store identifier.
• Target theme ID.
• Target theme name.
• Base theme ID.
• User prompt.
• Changed files.
• Git commit IDs.
• Validation result.
• Deployment timestamp.
• Preview URL.
• Claude Code summary.
• Application version.

Undo

Undo should:

1. Load the previous application-created revision.
2. Refresh Shopify theme state.
3. Confirm the target remains unpublished.
4. Restore only the files managed by that revision.
5. Run Theme Check.
6. Show an undo diff.
7. Require user confirmation.
8. Push to the same unpublished theme.

Undo must never target a live theme.

15. Validation Pipeline

Before deployment:

1. Verify modified paths are allowed.
2. Reject symlinks escaping the workspace.
3. Reject credential-like content.
4. Parse changed JSON files.
5. Run Shopify Theme Check.
6. Verify the target theme is unpublished.
7. Present the change for user review.

A failed validation must block deployment.

Claude Code may receive validation output for a limited repair attempt, but deployment still requires a passing validation result and user confirmation.

16. Error Handling

Errors should be translated into plain language.

Examples:

• “Shopify Builder could not connect to your store.”
• “This theme became live after you selected it, so the update was stopped.”
• “The generated theme contains an error and was not uploaded.”
• “Claude Code did not finish the requested change.”
• “Your original theme files are unchanged.”

Logs should:

• Use structured events.
• Redact tokens and sensitive paths.
• Include correlation IDs.
• Avoid recording full credentials or environment variables.

19. MVP Acceptance Criteria

The MVP is complete when:

• A user can connect one Shopify store.
• Only unpublished themes can be deployment targets.
• The live theme can be used only as a read-only base.
• The user can create a new unpublished theme.
• The user can update an existing unpublished theme.
• Claude Code can modify an isolated local theme.
• Claude Code cannot access Shopify credentials.
• Theme Check blocks invalid deployments.
• The user reviews changes before pushing.
• The user can open the resulting preview.
• Every successful change has Git-backed history.
• Undo works for application-created unpublished-theme changes.
• No application path can publish or modify the live theme.

21. Key Architectural Decisions

1. Electron over Tauri: easier integration with Node.js, Shopify CLI, Git, and Claude Code.
2. Local-first: no hosting requirement and credentials remain on the user’s computer.
3. Claude Code edits only: deployment remains in trusted application code.
4. Immutable theme IDs: names are display values, not security identifiers.
5. Repeated safety checks: theme roles can change after initial selection.
6. Git-backed history: every generated change remains traceable and reversible.
7. Explicit user deployment: generation does not automatically upload changes.
8. No live-theme functionality: publishing and live pushes are absent from the product, command policy, and IPC surface.
